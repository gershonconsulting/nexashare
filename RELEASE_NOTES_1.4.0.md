# NexaShare 1.4.0 — October 7, 2026

Application release; Chrome extension remains 1.2.24.

- Referral links persist for 30 days and are carried through the server-side LinkedIn OAuth state. Only new accounts receive attribution. Self-referrals and matching-email referrals are excluded. The dashboard tracks registrations, first confirmed repost activation, and paid conversion without exposing invitee emails.
- Both parties earn 30 bonus access days after a signed, paid Stripe Checkout event. `/api/referrals/stripe-webhook` requires the existing application's `STRIPE_WEBHOOK_SECRET` to be configured in Cloudflare and the corresponding Checkout events to be subscribed in Stripe. Until configured, tracking works and the dashboard explicitly marks payment rewards pending. Credits are unique per referral and recipient. Checkout links attach account ID and prefilled email; the webhook verifies both ID and paid customer email. This does not implement the separate subscription billing/enforcement system.
- Reporting shows complete personal account totals for 7, 30, or 90 UTC calendar days, including quiet days, days with no activity, and the current incomplete day. Metrics are computed in D1, independently of the 100-row repost-history display limit. Success = confirmed / (confirmed + failed); skipped and already reposted are excluded. No attempts is N/A.
- Intelligence calls Cloudflare Workers AI through `env.AI`. Wrangler defines the AI binding; no user key or external AI provider is used. Default model: `@cf/meta/llama-3.1-8b-instruct-fp8`. A Worker `AI_MODEL` variable can override it. Analysis uses full-period account metrics, up to 30 sources, and up to 60 recent confirmed repost snippets. It does not claim access to LinkedIn engagement statistics. Post content is treated as untrusted data, and model output is displayed as text. Saved reports refresh hourly; a per-user database lease limits generation to one request every 10 minutes across all periods.
- Daily report metrics now cover all outcomes rather than the newest 100. Recorded outcomes establish activity even when a run signal is missing. Subjects identify the reporting date, success rate, confirmed reposts and failures; the report shows health and a comparison with the previous day.
- Weekly user reports cover the seven completed UTC calendar days before Sunday, show a daily breakdown and include success rates. Weekly administrator reports show aggregate and per-user success rates alongside extension health. Administrator daily subjects summarize actual outcomes.

Validation: eight test suites, including real SQLite integration tests for date boundaries, totals beyond 100 outcomes, account isolation, referral exclusions, signed payment validation, duplicate credit prevention, bonus-day expiry, and Workers AI cache, concurrency and failure paths. Deployment applies D1 migration 0013 before deploying the Worker and assets.
